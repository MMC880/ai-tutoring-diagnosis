# AI API 与中转接入：需求边界记录

日期：2026-11-04。用户提出接入意向；尚未选型、编写接入代码、购买额度、保存密钥或发送真实学生资料。本文件不是完整技术架构或服务推荐。

## 用户方向

先做 10 人试点的山西初中数学软件，考虑通过中转服务调用 AI，未来扩展物理、化学、英语。每生档案保存在电脑本地；机构购买，首版老师使用，上传学生作答材料；学生端与家长客户保留后续方向。

最新明确实施顺序：一期先在 WorkBuddy 里试用，后期再做自己的本地软件并接 AI API/中转。一期使用何种 WorkBuddy 模型配置、是否需要自定义 API，尚未核实，不假定其支持任何指定中转；当前仍不开展接入或付费。

## 本轮核对的通用概念

- [OpenRouter 官方接入说明](https://openrouter.ai/docs/quickstart)展示一个 API 入口访问多个模型的聚合模式；这里只用来确认该类接入方式存在，不代表已选择或推荐该服务。
- [官方用量说明](https://openrouter.ai/docs/cookbook/administration/usage-accounting)分别记录输入、输出及其他适用 token 用量和费用。模型种类多、token 用量、账户额度与实际价格是不同指标，不能仅凭模型目录推定使用成本。
- [官方隐私说明](https://openrouter.ai/docs/guides/privacy/data-collection)指出请求会经过不同处理节点，并分别说明日志和上游数据处理。具体条款及默认设置可能变化，实际服务需在选型时重新核实；本地存档不直接决定 AI 请求在何处处理。

上述文档是公开说明，未进行该平台实际 API 测试，也没有验证某个国内中转站的合法来源、稳定性或真实性。

## 选型之前要明确的业务要求

1. 哪些任务实际需要 AI：读图识别、公式理解、辅助批改、错因建议、讲解和练习分别验证，不能只比较模型数量。
2. 单次作业的原卷/答案是否需要重复发送，哪些历史证据确有必要使用；不能默认每次发送整个个人档案。
3. 学生姓名、班级标识、照片、作答和成长记录中，哪些可向服务发送，必要授权如何确认。
4. 中转方与上游模型的日志、保留、训练使用、处理地点、可控制设置及合同条件需要分别核实；去掉姓名不等于完成全部隐私工作。
5. 以 10 人、实际页数和预期频率估计作业成本、复核时间、失败重试与费用上限；目前没有数值预算或服务质量保证。

## 已确认的数据与使用边界

用户已确认：完整成长档案、姓名等身份信息和身份对应关系保留本地；外部 AI 仅接收经明确授权、去除身份标识后的必要题目和作答。用户认可授权是必要前提，具体资料范围、去标识措施、授权落实方式、服务日志与上游数据处理条件仍需细化。本轮没有取得或使用实际授权文书、没有调用 API 传输真实学生资料，不把业务原则的确认冒充已完成数据处理验证。

学生先完成老师布置的作业/试卷，再进入 AI 辅导管理；结果必须经老师复审确认才能给学生看，审核不限于疑点。审核组织方式与交付渠道待定；学生端后续另定，不据此批准自由问答功能。当前不索取 API 密钥或要求用户在聊天中提供凭据。
