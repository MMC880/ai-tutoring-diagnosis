# 晋学智辅：哪里不好用，直接这样告诉我

不需要懂代码，也不必先判断是Bug还是操作问题。

把下面一句话发在当前聊天即可：

> 我在【什么位置】，想【做什么】，做了【操作】，结果【发生什么】；我希望【应当怎样】。截图或录屏可选。

例如：

> 我在AI Agent里，刚存完三张作业，想接着让它分析。它又让我选照片，我希望能接着处理刚才那份。

也可以只发“这里不好用”加截图，我会根据按钮文字、错误提示和窗口位置定位。无需补全每个字段。截图中不必包含密钥、学生姓名等信息；有学生材料时优先使用测试称呼。

## 反馈发到哪里

- 最简单：直接发在这个 Codex 聊天里，截图、录屏或一句话均可。
- 换新聊天：附上本文件和[真实体验审计](UX_AUDIT_2026-11-11.md)，再说问题。
- 想在本地记录：复制下面一小段，写到自己的普通文本文件里即可；这不是必须步骤。

```text
我想做：
哪里不对：
截图/录屏：可不填
希望变成：可不填
```

本轮只提供这个文本反馈方法，没有增加软件内“反馈”按钮、自动上传或遥测功能。

## 收到反馈后怎么处理

1. 我先找到对应窗口、操作路径和代码；尽量自己确认版本等技术信息。
2. 用独立测试资料复现，保存截图/步骤/必要日志。复现不了明确标为“待复现”，不猜成已确认Bug。
3. 给你说明当前行为、影响及最小修改方案，涉及资料保存/外发时说明边界。
4. 等你确认后才修改；修后复测原问题和直接相关路径。
5. 告诉你改了什么、怎么试、还有什么限制；不顺便增加功能。

## 我负责维护的定位记录

你不必填这张表，它是开发侧用的。

| 字段 | 要记录什么 |
| --- | --- |
| 编号 | 如UX-01，避免同一个问题重复讨论 |
| 状态 | 新反馈/待复现/已复现/方案待确认/已批准/修改中/已验证/待你试用/关闭 |
| 分类和优先级 | Bug、操作流程、UI布局、功能缺失；影响程度 |
| 版本与路径 | 具体版本/提交、主窗口或Agent、涉及学生/作业的测试标识 |
| 复现和证据 | 最少步骤、实际结果、期望结果、截图/日志位置 |
| 代码范围 | 模块/函数，而不是让你自己找文件 |
| 修改与验收 | 用户确认的方案、回归步骤、结果、未验证部分 |
