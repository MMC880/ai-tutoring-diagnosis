# 晋学智辅 2.0 真实 UX 体验审计

日期：2026-11-11。版本：2.0.0-preview.1；工程基线：`dd3b15b`。

结论：本地收件、教师指定错题归档、历史查询、知识点关联和有限的补练复测能够运行，但老师的一次任务被拆在两个窗口、两套上传规则和一张很长的页面里。已经复现了指令分流错误、成功后状态矛盾等问题。功能测试通过不足以证明教师能顺畅使用。

本轮只调查和记录；以下建议均未实施，也不代表用户已批准改版。

## 2. 现在实际有哪些界面

软件目前是**一个主窗口长页面 + 一个独立 Agent 窗口**，不是三个独立的“学生档案/登记作业/班级学情”页面。

| 位置 | 已实现的内容 | 本轮实际情况 | 尚未完成或限制 |
| --- | --- | --- | --- |
| 主窗口顶部 | AI 地址、模型 ID、密钥输入、文字连接测试、打开 Agent | 看过控件；打开 Agent 成功 | 未输入密钥、未测真实服务；“后端已连接”只表示本地服务可用 |
| 本地资料与备份 | 备份、恢复到空目录、选择下次资料目录 | 查过实现和按钮 | 本轮未点原生对话框；不引用历史测试冒充本轮体验 |
| 学科与学生 | 数学/英语/物理/化学；按称呼查找、确认新建 | 创建/切换合成学生成功 | 无常驻学生名册列表；四个按钮不代表四科内容全部完成 |
| 主窗口知识点与复习 | 作业/题号选择、知识点、原件证据、候选/教师确认、更正 | 实际关联、更新统计、下载原件 | 需要逐题填表；没有图内定位、快捷标签或自动候选回填 |
| 同一长页中的个人/班级统计 | 已确认知识点的作业次数、覆盖人数、证据 | 一人一份的确认结果可见 | 本轮未建立多班级/多人样本，不能据此宣称班级分析已通过用户验收 |
| 主窗口下部上传与聊天 | 第二套上传、老师说明、保存、导入摘要、对话 | 同图上传拒绝可复现 | 图片限制比 Agent 严；入口很深，与 Agent 功能重叠 |

| 讲解/三级练习/复测 | 内置顶点式示例、审核、无答案题面、复测历史 | 内置示例审核和复测实际保存 | 普通知识点需手工 JSON；未打通 Agent 内容到结构化草稿的直接交接 |

## 3. 核心任务实际要多少步

计数方式：填写一个字段、选择一次、点击一个按钮各算一步；上传一组文件算一步。滚动、切换窗口、阅读、数学判断和系统文件选择框内部操作另计，因此这些是**操作下限，不是教师用时**。以下从已打开的软件开始，不包含双击 EXE。

| 任务与起点 | 观察到的步骤 | 下限 | 结果/额外负担 |
| --- | --- | --- | --- |
| 新学生三图归档，从主窗口开始 | 打开 Agent → 选三图 → 填归档指令 → 发送 → 确认新建 | 5步 | 确实保存3张原件、教师错题3/5/8及回执；不用模型 |
| 现有学生归档，从主窗口开始 | 打开 Agent → 选图 → 填指令 → 发送 | 4步 | 信息明确时直接保存；有身份疑点才确认 |
| 当前 Agent 查历史，无附件 | 填查询 → 发送 | 2步 | `/api/intake/query`返回本地记录 |
| 整个审计窗口关闭重开后查回记录 | 主窗口填学生 → 选择/查找 → 打开 Agent → 填查询 → 发送 | 5步 | 已归档记录仍在；先前聊天已清空 |
| 主窗口确认一个知识点，学生/记录已准备好 | 选作业 → 选题号 → 填知识点 → 填证据依据 → 教师确认 | 至少5步/题 | 默认第1原件/第1页正确时才是5步；换原件/页码还要各1步；下载并外部查看另计 |
| 从 Agent 归档转到主窗口关联，主窗口尚未选学生 | 填学生 → 查找 → 上述关联5步 | 至少7步/题 | 已选学生时，新作业仍需手动刷新；没有从回执直达当前作业 |
| 内置示例补练到一次复测，从已确认知识点开始 | 准备草稿 → 老师审核通过 → 填复测原答 → 选结果 → 勾独立完成 → 登记 | 6步 | 包含实际写入；未含阅读三档完整答案和学生做题时间。下载题面再加1步 |
| 非内置知识点补练 | 点准备 → 收到不支持 → 展开录入 → 准备并粘贴JSON → 保存待审… | 未闭环 | 本轮复现到报错和JSON入口；没有用编造内容假称通用补练成功 |

## 5. 可以直接复现的步骤和代码位置

### UX-01：带附件查询变成模型请求

1. 在Agent选择任意合成图片，等待文件清单显示。
2. 输入“学生测试甲最近一个月错过哪些题？”，发送。
3. 观察到模拟回复“图片数量1”，请求为`/api/intake/analysis-image` + `/api/chat`。
4. 清除本组材料后同样查询，返回本地30天错题记录。

对应：`v2/src/intake.tsx`中`handle()`的查询条件受`!materials.length`限制；`v2/src/main.tsx`的模型适配器随后收集分析图。本轮没有真实外发；若配置服务，存在错误进入模型路径的风险，真实外发结果未测。

### UX-02：分析历史材料被当作新归档

1. 已有成功回执；当前未选文件。
2. 发送“再分析刚才归档的那张作业”。
3. 看到要求重新添加材料的错误，未发出`/api/chat`。

对应：`v2/src/intake.tsx`的`/归档|存档|(?:帮我|请)保存/`。本轮两次独立操作复现，不把第一次脚本等待超时掩盖为测试成功。

### UX-03：归档成功却仍称未归档

1. 选一张此前未归档的图片。
2. 用明确学生、学科、错题号的指令归档。
3. 回执为“已归档并回读”，上传区仍为“尚未归档”。

对应：`v2/src/intake.tsx`的`addFiles()`与`accept()`；后者清空材料但未同步接收说明。
