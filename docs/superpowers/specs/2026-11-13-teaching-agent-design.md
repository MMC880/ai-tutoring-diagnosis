## 1. 产品要解决什么

晋学智辅是给教培老师用的本地教学 Agent 软件，接近一个专门处理教学资料的 WorkBuddy。老师交代任务，Agent 调用软件已有工具读材料、查历史、分析与保存；软件负责可靠地管理学生、原件、档案、MD、Skills 和任务过程。

老师不应为了让 Agent 使用已经登记的信息，再填一轮表单或手动搬运所有历史。老师仍负责教学、批改确认及给学生布置内容。软件用可核对的记录帮助老师看到“这次问题和以前哪里可能有关”，而不是用漂亮回答代替实际读取和保存。

长期闭环保持为：作业 → 错题记录 → 错误类型与知识点归纳 → 针对性训练 → 复测反馈 → 更新学生档案。本批只补其中的 **Agent 按权限读两次作业、引用依据、保存待确认分析、重开继续并纠正**。

四科学科入口继续保留，记录分科管理；第一套教学验收仍使用数学。首批约十人、山西初中中考场景是试点背景，不限制以后年级扩展，但不因此在本批建设全学段课程库。

## 2. 已确认的需求与本批 MVP

以下是用户已确认的方向；后文具体工程安排属于待审设计。

| 编号 | 老师应能完成的事 | 本批边界 |
| --- | --- | --- |
| R1 | 将同一学生、同次作业的照片/PDF 归档，明确交代学生、科目、日期及教师指出的错题 | 沿用现有归档。日期可待补；重名、归属冲突要询问；原件保留，不以 OCR 成功为前提 |
| R2 | 自然语言说“分析这次第 5 题，看看和以前有什么关系” | Agent 自动选合适教学流程，不要求老师选 Skill；读当前材料与该生同科历史摘要，必要时看授权图片 |
| R3 | 看到 Agent 真正做了什么、依据是什么 | 显示实际工具结果、作业/题号/材料来源；未读图不说看过，未保存不说已保存 |
| R4 | 一次确认本任务范围，然后连续处理 | 范围内不逐工具反复确认；额外历史原图另请求；重开不自动恢复外发许可 |
| R5 | 重新打开该任务，看到旧讨论、工具回执、笔记并继续 | 本地保存完整任务对话；不承诺自动续跑中断的模型任务，不默认重发全部历史 |
| R6 | 在对话里说“不是第 5 题，是第 6 题” | 明确修改形成新版本与修改回执；旧稿保留，其余 AI 推断不因此获得教师确认 |
| R7 | 阅读、复制或交回修改过的 MD | MD 可读、可改、可长期留存。外部改稿作为修订候选，经来源核对后形成新版本，不静默覆盖正式记录 |

**本批完成的标准：** 老师在同一个任务中交代目标、确认一次范围，Agent 实际读到同生两次数学作业的相关记录；能引用具体题号及材料，区分同知识点与同错因，保存并回读待确认 MD；重开后可继续，对话纠正产生可追溯的新稿。

**不纳入本批：** AI 分析转正式学生事实、发布练习、自动三级训练/复测、四科完整教学 Skill 库、全自动批改、任意本地文件/终端工具、教学资料全库建设、PDF 新渲染引擎、家长端、多人云平台、收费、界面全面改版。保留现有功能，不删旧数据；这些方向以后单独验收。

历史证据中，两次合成作业的模拟模型流程已通过。最新真实模型请求为 2026-11-12 的 HTTP 401，未产生本轮自主历史工具调用、读图或分析 MD；本地回归通过不代表真实验收成功。本批文档不重试凭据，也不把更换运行组件当成修复认证。

## 5. 老师实际怎样完成这个任务

示例使用脱敏/合成学生 A：11 月 1 日数学作业第 3 题、11 月 12 日数学作业第 5 题。测试题与答案来源必须写清，不能把 AI 自编答案标成教师标准答案。

1. 老师选学生 A、数学、本次作业，或沿用已有归档入口交材料。已有归属不重复填写；缺关键归属才问，姓名不能代替学生内部身份。
2. 老师说“分析这次第 5 题，看看和以前有什么关系”。Agent 选“关联历史问题分析”流程，用简单中文说明本次要读什么、保存什么。
3. 老师看一份任务范围说明并确认：当前作业材料、同生同科历史结构化记录、保存待确认笔记。并展示所用服务/模型；不默认把全库照片放进请求。
4. Agent 按需调用工具。先摘要/结构化记录，再读必要原图；工具卡显示真正读过的作业、题号、页码/文件及结果。文字检索未命中不能说“从未错过”。
5. Agent 输出：本次观察、过去具体记录、知识点关联、错因假设、尚不确定的地方；保存待确认 MD 并回读后给出真实路径/版本/校验回执。保存失败仍保留已有材料及已执行回执。
6. 老师纠正题号时，新稿只按明确纠正更新。第 5 题的图片不能换个标题就作为第 6 题依据；要重新取第 6 题证据，取不到则标无法判断。原错因未获确认，不写为长期薄弱。
7. 退出重开，在该生该科作业下打开同任务，旧对话、工具回执、各版笔记可读；继续外发前重新确认范围，旧运行不自动续跑。

本批不让老师在任务中再编辑 JSON、不要求手选开发 Skill、不把一个普通模型回答包装成已执行多步骤任务。

## 6. 数据职责与关系

| 对象 | 权威内容/用途 | 关系与限制 |
| --- | --- | --- |
| 学生、学科、作业、作答记录 | 既有 SQLite 有效记录与修订；正式记录来源和状态保留 | 一名学生多次作业；上传/重传/改判不能冒充新作答 |
| 原始文件 | 不覆盖的原件字节与哈希 | 一份作业可多文件/页；哈希证明字节身份，不证明学生归属或模型已读 |
| 教学任务 | 本地对话、目标、当前材料、任务范围说明、运行/笔记关联 | 本批任务固定一个学生、一门学科、一个主作业；历史作业通过工具按需引用。新作业可另建任务；不静默更换归属 |
| 消息与工具回执 | 稳定消息/调用身份、顺序/父关系、实际状态、来源与操作结果 | 同一任务可多轮请求；工具结果来自后端，不由模型文字伪造。保留原始消息，纠正另写消息/新版本 |
| 单次 Agent 运行 | 一次用户指令的执行记录、预算、实际调用、停止/失败及已提交结果 | 同任务多次运行；对话恢复与运行续跑分开，不做通用持久任务调度器 |
| 待确认分析笔记 | 版本、关联任务/运行、来源快照、作者类型、修改依据、发布状态 | 保持 AI_PENDING_REVIEW，不更改教师正式错题或知识关联；后续正式入档需另一个获准流程 |
| Markdown | 人可读的归档历史快照或明确版本的待确认笔记 | 不是任意文件改完自动生效的第二个数据库；外改作为候选输入，原稿/外改原件均保留 |

**助手提出的技术取舍，等待审阅：** SQLite 是任务/消息/笔记版本的唯一索引与状态来源；MD 是可回读的版本文件。继续采用 assistant-ui LocalRuntime + history adapter；SDK 不另建一个会自动发送全部旧对话的会话库。SDK 只收到软件按当前授权筛选的本轮上下文。

任务标识、表名、索引和类的边界由实施者确定；延用已有库，做兼容、可回退的增量表及 schema 版本检查。迁移前先做独立备份，旧库/旧 MD 不覆盖，不对 1.0 做自动迁移。不要把 SDK 的 SQLiteSession 另立为学生档案真源。

## 7. 任务授权与对外材料

任务绑定学生、学科、主作业，授权由服务端核对，不能以 prompt、界面勾选或 SDK 工具列表代替。工具不能接受模型自定的任意磁盘路径。

- 一次确认覆盖：当前主作业所选材料、该生该科结构化历史、待确认笔记保存；对话内同范围连续请求复用授权。
- **助手默认：** 授权只在当前应用会话内有效；退出/后端重启、主动撤销、学生/学科/主作业或服务配置变化后失效。它不写入可重放的历史授权，不跨重开自动启用。
- 追加历史原图只针对明确的作业/文件/页请求授权。原图许可不得由“允许历史摘要”推导；更多文件或另一个模型服务都需更新说明。
- 授权范围内的历史对话仍需按来源过滤后选必要内容；本地保存和界面恢复不表示图片、全档案、全部旧话语可重新发送。图片已授权也不默认每轮重传。
- 学生称呼、班级、联系方式及完整档案留本地；外发用本地映射后的测试/学生代号和必要内容。照片仍可能带身份信息，须沿用已有裁剪/遮挡能力或先准备脱敏材料；不宣称已自动可靠去标识。
- 图像/MD/题干中的指令仅是材料内容，不能提升工具权限；不加入网页、邮件、shell 或其他 Agent 的任意写文件权限。
- Key 继续当前用户 DPAPI、不回显、不进 MD/日志/包。不开默认外部追踪；无自动重试、切模型或切端点。

用户明确指出的错题仍可走已有本地归档，这不依赖模型服务在线；本批 AI 分析和对话纠正只改待确认分析。

## 8. 成熟运行时接入的通过条件

先在 E 盘项目缓存及隔离环境中固定候选正式发行版，检查与 Python 3.12/现有锁文件的依赖冲突、官方样例、许可证和数据外发默认项。验证结束写结论，不能先把全项目依赖升级来迁就 SDK。

兼容验证通过后，以窄适配器接现有工具与配置；旧实现保持可比较/回退，单次运行只能由一个执行器处理，不允许新旧循环都跑。必须验证：

1. 指定 Chat Completions 兼容端点、工具参数/调用身份、图像内容能够正确传递；没有暗中改用默认服务或 Responses 协议。
2. 保留现有最多四次模型请求、每轮最多四个工具、图像上限；工具串行，权限在工具执行时再次检查。SDK 的 turns 计数不能替代实际请求/工具计数。
3. 显式关闭 tracing 和自动重试，固定端点与模型；失败回执和日志不泄露 Key/图片 base64/完整身份。
4. 工具拒绝、无效参数、401/429、超时、预算耗尽、保存后模型失败，都不能被映射成成功或本地模拟结果。
5. 停止后不发起新的模型/工具调用；已经提交的保存照实保留。正在进行的上游请求能否取消单列，不承诺供应商停止计费。

本地替身可验证协议/工具行为，报告必须标 SYNTHETIC；不能用它替代真实供应商验收。兼容不通过则停止生产替换，交付具体原因与保留成果；如需换组件、升级核心版本或改路线，另提最小方案。

## 9. 运行状态、重复、纠正与 MD 失败

这些是为了可信回执所必需的最小连接，不扩大为工作流平台。

- 为任务、运行、工具操作、消息和笔记版本建立稳定身份；前后端重试同一已提交操作回同一回执，不生成第二份笔记。同一操作身份带不同内容要明确冲突。
- 正常运行、成功、失败、停止、结果待恢复分别显示。窗口关闭/后端重启后，原运行标中断/待核，不自动重发模型请求；先查询已经提交的结果。
- 工具卡只显示安全参数摘要和真实结果：读到、未命中、材料不可读、无权限、保存成功/保存未完成。模型说“我将读取”不能显示“已读取”。本批先保证最终回执显示，不承诺 token 逐字流式动画。
- 对话与运行回执写入失败时不能静默声称已永久记住；保留可见错误与能恢复的草稿，重开后区分完整消息和中断记录。
- 笔记保存把修订及待导出记录写入同一 SQLite 事务，再以现有安全文件写入/回读形成版本 MD，最后标完成。只有 MD 回读/哈希核对成功才显示“MD 已保存”；否则显示“记录已保存，MD 待恢复”并可幂等重建。不宣称跨 SQLite/文件原子事务。
- 外部修改 MD 的原文件不自动导入。通过已有附件/导入路径交回时先保存候选及来源版本；无法确认对应任务/稿件则询问，不在错误学生档案内套用修改。
- 纠正依赖的旧笔记/正式来源若已修订，使用期望版本检测冲突；不能把迟到回复盖到新稿。主窗口/Agent 并发修改同任务时提示冲突，保留两次输入；不建设实时协作平台。

现有 PDF 若只能存档而不能看图，要明确“本次未读取此页”；图片失败不按答案补作答。检索只覆盖当前受支持的结构化范围，没有命中不能推出从无错误。无法重建旧分析时保留旧稿并说明，不编造来源。

## 10. 第一批教学流程内容

沿用 Agent Skills 格式，显示中文名称与说明，本批只建立与验收任务直接相关的“作业关联历史分析”流程；归档、查档、纠正属于它可调用的现有/新增受限操作，不另外扩成十个 Skill 管理页面。

流程根据老师意图与已选材料选择：纯查档/明确本地归档继续走已有工具；需要分析关系时加载对应教学说明。目标不清、无适用流程时明确问，不自动套训练或判定心理原因。

输出最少包括：当前题号/材料位置、可观察作答与批注、老师已确认部分、与历史的知识点联系、错因假设及反证/未知、实际来源、待老师核对项、笔记版本状态。相同知识点不等于相同错因；教师没有提供偏好时采用通用初中数学解释，不伪造教案来源。

流程内容与工具运行分别验收：模型可以没选对流程/没调工具/数学分析错误，即使 SDK 正常也要记失败。不能把预设二次函数标签当成模型自主发现。

## 11. 验收：必须留下什么证据

所有测试用独立脱敏/合成目录，不改正式学生记录。不再等待新增学生材料即可完成本地工程验证；真实模型部分需有效且获准的服务配置。

| 验收项 | 应看到的证据 | 通过边界 |
| --- | --- | --- |
| A1 原成果保留 | 原件/正式记录前后哈希或有效快照相同；已有归档/知识/备份相关回归 | 本批笔记和任务不能改动教师已确认事实 |
| A2 运行时兼容 | 固定版本、依赖差异、协议与工具/图像替身测试、关闭重试/追踪的证据 | 本地通过不叫真实模型通过；失败停止替换 |
| A3 自主流程与工具 | 仅自然语言指令；记录实际模型响应/工具调用身份、参数摘要、返回 | 教师不手选 Skill；不由测试脚本预填“模型选择”冒充真实自主 |
| A4 任务权限 | 同任务一次确认；合法连续读取；跨生/跨科/额外历史原图拒绝测试 | 重开、撤销或变更服务后不可用旧授权外发 |
| A5 两次作业证据 | 具体 assignment、题号、文件哈希/页、结构化修订；记录实际读过哪些图 | 只给模型本次图，不默认全部历史图；未读内容不得引用成已观察事实 |
| A6 分析质量 | 本次第 5 题与以前第 3 题对照；同知识点与同错因分开，未知明确 | 模型自主输出再与预设可核对答案比对；错误也记录，不声明批改准确率 |
| A7 工具展示 | 实际 Electron 中读、拒绝、不可读、保存卡与后端回执一致 | 一个后端操作只执行一次，不靠前端重新调用来补显示 |
| A8 待确认 MD | MD 实际路径/版本/hash、保存回执及二次回读；正式记录未变 | “已保存”须有写入结果；笔记始终待确认 |
| A9 重开续聊 | 同任务稳定消息/工具/笔记恢复；切学生/科目不混档 | 无自动运行/外发；重开后的继续是新运行 |
| A10 对话纠正 | Q5→Q6 新稿、旧稿不变、修改范围和新证据明确 | 不把旧 Q5 图当 Q6 图，不批准其余分析 |
| A11 外改 MD | 原稿与外改候选保留、版本/归属核对、冲突测试 | 没有静默文件监控回写正式表 |
| A12 失败与去重 | 401/429、断连、停止、保存后失败、重复操作、MD 导出中断回读记录 | 已提交结果可查；无自动重发；重开不重复存稿 |
| A13 备份与恢复 | 新任务/消息/笔记随隔离备份恢复，旧档案可读 | Key 和授权不随学生资料备份；不做全新迁移平台 |
| A14 教师体验 | 老师实际交代/继续/纠正，记录操作次数、重复输入及困惑 | 工程通过和老师体验分开，不先承诺省时比例 |

真实验证采用现有服务地址与模型配置，先无学生资料的认证探针，再执行同一两作业案例；日志保留状态码、时间、调用数、工具结果、文件前后差异。最新 401 未解除前，真实验收保持 BLOCKED_AUTH，不重复消耗失败凭据，也不以替身或历史部分成功覆盖。

## 12. 阶段顺序与停止点（待批准后细化，不是已执行计划）

| 阶段 | 最小交付 | 进入下一阶段的条件 |

## 13. 审阅时需要知道的助手取舍与风险

**用户确认的是产品选择，不是以下每项工程细节。助手提出：** 固定学生/学科/主作业的任务；会话内授权；LocalRuntime/history adapter 与单一 SQLite 任务记录；先隔离验 SDK；笔记版本与待导出恢复；先最终工具回执、不追求逐字流式。它们旨在复用现状、减少改动，用户可在审稿时调整。
