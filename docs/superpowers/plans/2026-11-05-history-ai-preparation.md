# 补练历史与AI接入准备 Implementation Plan

> 执行采用 superpowers:executing-plans；用户已多次要求继续连续实施，沿用本地技术方案，不重复索取开发许可。TDD先验证缺口，最后一次独立审查。

**Goal:** 保留补练各版本与审批证据，并准备可预览、逐次授权的AI草稿接入，不把模型返回直接当正式档案。
**Architecture:** 沿用app/ Python、SQLite与普通网页。补练版本新增快照表，现有练习行作为最新投影。AI适配边界与UI独立，具体协议以用户待提供的服务商文档为准。
**Tech Stack:** 现有依赖；仅必要时使用Python标准库HTTPS，不安装新Skill或SDK，不更改系统网络配置。
**Spec:** PRD.md、MVP_SCOPE.md、docs/design/LOCAL_TRIAL_DELIVERY.md及本轮继续实施授权。

## Global Constraints

- 仅本项目app/与文档，不改WorkBuddy旧包或其他项目。现无独立Git仓库，保留v0.1源码包，不造提交。
- 原卷与复测、身份与外发材料分离；不做心理档案。
- 旧已批准练习可按明确选择版本处理迟交；旧未批准版本不能导出学生版或录入复测；旧版不可重编辑与补审批。
- AI不得读取完整档案、身份映射；外发前展示实际内容与目的，教师明确确认；密钥仅本机输入、内存使用，不进入数据库/日志/备份/导出。
- 服务文档、模型未齐前不猜服务商、不做真实外部调用。模型草稿与人工整卷确认仍分开；未知能力与真实费用不标通过。
- 迁移前为当前本地库留备份，启动切换只处理本项目拥有的服务，不按进程名终止。

## Review Focus

旧审批不串给新版本；旧提交绑定原题面；升级旧数据库不伪造已遗失版本；外发载荷不含档案或身份字段；重试不重复收费调用；模型返回和题目内容不能越权写正式档案。
