# v0.21 按知识点查看补练复测进展

目标：老师在每生同类问题卡片中，直接看到该知识对应的补练与复测进展，区分原卷历史错误和补习后的新证据。沿用本地单用户网页/Python/SQLite，不增加字段写入、schema、模型调用或自动掌握判断。

方案：复用learning_journey固定原题确认来源，按与learning_analysis一致的稳定知识身份只读关联到当前知识组。已审核条目跨名称、题型和资料版本匹配；同名不同条目和未关联标签分开。关联依据是建立练习时的原题确认，不用当前草稿/新关联倒推旧练习。

每组显示补练组数、累计复测记录数，以及各练习最近一次记录对应的观察状态：待审批、待复测、材料待核、完成条件待核、仍需补齐、有提示需独立复测、独立答对仍需观察。每组练习列明来源确认版本、当前练习版本、是否有待审题面、已批版本数、历史复测次数和最后记录的条件/结果/题面版本。最近指该练习写入顺序的最后记录，不是实际考试日期或全知识点的统一诊断。

同一知识下多组练习分别保留；不以一组独立正确抵消另一组待补，也不删除原错题。原题改知识关联后，旧练习仍按固定旧来源；没有当前知识组可对应或旧来源缺失的练习，仅提示未归到当前组的数量，完整内容仍保留在下方补习与复测过程。

UI增加只读摘要与“定位完整补习复测过程”按钮，核验当前学生/知识组/练习身份后只在本页滚动并聚焦既有过程卡。不会保存、批准、生成题目或跳到错误学生。保留已有安排补练入口和完整过程链。

实现：learning_analysis抽出唯一知识身份函数，新增knowledge_followup.py为analysis组附加followup及未匹配计数；Store.profile计算一次journeys后调用。新增followup-panel.js渲染/定位，其他页面兼容。缺数据保持空状态，不从合成样本或记录时间补造真实表现。

验收：先专项RED/GREEN，再隔离浏览器检查身份、各状态、旧版本/旧知识来源、只读定位及窄屏；完整Python、档案/班级/连续审核回归及独立审查。备份后更新本机0.21并核验业务数据不变，白名单打包/本地提交。真实识读、知识语义、独立作答及净省时仍待教师验证。
