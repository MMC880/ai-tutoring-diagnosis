# v0.22 补练复测待办

目标：老师按已有批次集中查看各学生补练的下一步处理线索，准确打开对应练习，减少逐生翻档案。沿用本地单用户网页/Python/SQLite；不新增学习日程、到期判断、自动提醒、审批或发布。

方案：新增只读practice-queue接口和独立“补练复测待办”页。复用learning_journey固定原题与练习版本、最后写入复测，返回最小任务元数据，不提供答案、讲解或原件正文。批次/状态筛选在本机显示，未建练习的学生不算漏交，空批次保持无记录。

每组练习只列一行：学生编号/称呼、来源批次/原卷/题号/确认版本、当前练习版本与审批状态、旧版已批版本、累计复测及最后录入条件/判定/题面版本。来源缺失优先“来源待核”；当前有待审题面优先“题面待审”，旧复测观察仍单列，不套到新版。当前版已批准但没有该版本复测时必须等待复测；旧版迟交不能覆盖当前版观察。其余为等待复测、材料/条件待核、仍需辅导、有提示需独立复测、独立答对后续观察。按固定处理类别、学生编号与练习ID稳定排序，不算掌握率、等待天数或实际到期。

点击“打开这组补练”只导航到正确学生/原卷/确切当前练习。老师随后按原界面选择版本、审题、导出或录入，不由待办自动开记录/批准。点击前锁定显示行；重读清单、bootstrap及最终清单，核对练习身份/版本/状态/固定来源、原卷版本和最新复测ID；过期停止并提示刷新，不改跳其他学生。切页、换批次/筛选、打开窗口使迟到操作失效。

新增practice_queue.py与queue-panel.js，learning_journey抽出共用观察纯函数并保留既有跨版本过程语义；待办的当前版本观察单独按版本筛选。其他页面复用；无schema或写接口变更。清单失败禁用旧行，重试恢复。页面不依赖已有当前卷也可进入空状态，窄屏可用，所有姓名/标签转义。

验收：后台计数/类别/隔离/固定来源/只读HTTP，页面筛选与精确导航/更新/迟到响应/空状态/窄屏，完整Python及档案/补练跟进/连续审核回归、一次独审；备份后更新本机0.22只读核验资料未变，白名单包与本地Git提交。真实教学效果、独立条件、识图质量仍需实测。
