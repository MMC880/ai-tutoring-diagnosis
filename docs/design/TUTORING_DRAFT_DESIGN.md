# v0.6 原题补讲与三级练习候选

2026-11-05。沿已确认的照片→问题记录→讲解与三级补练主线，复用现有AI任务、逐次授权、练习草稿／审批及复测。无新服务商或依赖，本轮仅合成假接口验证，不从聊天装载密钥或真实外发。

## 行为

1. 当前整卷已确认，原题为错误／部分正确且无识别疑点，才开放辅导候选任务。来源绑定学生、本卷版本、题号和原确认快照；单次只取这一题，不取完整成长档案或其他学生材料。
2. 老师可在预览前清除题目文字中的身份信息，保持题意及学生原作答。请求只包含必要原题、作答、核对参考、知识点／题型和待核实备注；原确认快照仅本地。修改不改写原题档案。
3. AI返回六段教师教案草稿：原题讲解、题目复盘、知识点归纳、通用解题模型、分类变式、举一反三建议，以及基础／综合／迁移三道候选，各含题干、教师答案与说明。严格核对字段、三档完整性、长度和重复题面，格式通过不代表数学／课程适配已经正确。
4. 所有结果标为需教师核验；不采信模型自称已验证／已批准，不执行材料中的指令或工具。老师选择一档并明确同意后，只创建DRAFT练习，六段教案合并到教师讲解字段。学生练习版仍仅题面，教师答案／教案不自动发布。
5. 每任务每档最多创建一次，重复点击同档返回同一练习，不覆盖老师后续修改；其他档可在单独选择确认后创建，不自动发三套。创建练习和记录映射在同一SQLite事务，失败整体回滚。
6. 来源版本已变／改判／有待审修订则阻断新的应用。已创建同档的重复请求只返回原记录，不以幂等读取为新批准。旧任务／原确认／旧练习和审批保留，复测沿用已批准的确切练习版本。

## 结构与恢复

新增tutoring.py负责契约、提示规则、教案组合和恢复核验；AIService mode=tutoring_generate。任务metadata存source_snapshot/source_question_id与practice_drafts（level→exercise_id/created_version），无新业务表。Store内部复用同连接_create_exercise，保证与任务映射原子写入。

恢复前核对源确认快照确实存在且一致、题号与学生对应、已用候选的练习V1来源／档次／内容一致。练习后续修改保留V1，不因此误拒合法备份。旧无此模式备份兼容。

## 边界

本轮实现候选生成通道，不保证新题数学正确、全初中覆盖、难度适配或真实模型表现。可信合成案例单独用现有SymPy核对数学，不把该核验推广到任意AI输出。没有学生端发布、支付或心理功能；密钥本机输入，外发逐次授权，失败／未知保留用量且不自动重试。

本轮同时统一上轮遗留的“知识点／题型”字段文案为“知识点”，题型继续独立；这是已列待办，不改变历史标签。
