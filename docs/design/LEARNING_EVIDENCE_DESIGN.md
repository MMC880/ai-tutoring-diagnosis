# v0.5 持续问题证据与补练衔接

2026-11-05，沿照片后的学习反馈主线继续开发。已有逐生整卷确认、历史、补练审批及复测，不重复搭建。新增可选题型标签、确认记录的跨次汇总与回原卷／安排补练入口。

## 老师看到什么

- 每个知识点＋题型的已确认错误／部分正确／正确／待核对／缺材料数量。
- 这些问题出现在多少份不同作业、哪些原题、哪些步骤及老师核实备注；同卷多题与跨卷反复分开显示。
- 复测继续单独展示，原错题不删，一次正确不标掌握；错误线索不等于确定知识缺失。
- 从当前已确认且错误／部分正确的原题安排三档补练；原卷有待审修订时先回去复核，不使用旧审核许可。

## 证据口径

1. 只读最新教师确认的每卷每题状态。同卷改判保留历史但只算一项；草稿修改不进入汇总。
2. 增加可选question_type，最多200字。旧记录无此字段时兼容。知识点与题型使用去首尾及折叠空白后的相同文本归组，不自动合并近义词、不推断未标标签；两者都空的列为待标注。
3. 汇总只描述“不同作业中出现错误”等事实，不新增掌握概率、弱点认定次数或心理标签。至少两份作业的错误是跨作业反复线索，两道同卷错题仍是一份作业，不等于两次独立测试。
4. 对同一学生，同一组PNG/JPEG作业原图哈希及同题号重复录入，保守按一份题目证据计入；该图片组不同题也只算同一份作业，使用最后确认的记录；参考答案附件不参与。原始档案和班级统计不删不改。没有作答图片时仅按不同作业计数，不声称已证明独立作答。
5. 照片重复判断保守：若老师重复使用同一张空白原卷图配不同人工答案，也会视为相同照片证据；页面说明此限制、保留所有历史。不能用本文替代明确提交真实独立作答。
6. 不把补练复测计入原卷反复错误次数，不把PENDING/MISSING作为错误。题型由老师标注；文字AI可提出候选题型，仍需人工核对确认。

## 实现边界

新增learning_analysis.py只读聚合，由Store.profile提供learning_analysis。现有SQLite JSON字段支持可选标签，无新业务表，不回写旧确认事件。新learning-panel.js呈现分组与来源路由，沿用原补练接口和审批。没有新外发字段或服务商依赖；AI系统指令可请求候选题型，但不发送学生档案。

不自动生成新题、自动诊断知识匮乏或自动发布；完整初中知识目录和模型归类准确率仍待验收。所有本轮测试使用隔离合成数据，不对本机未确认卷补造教师确认。

审查修正：分组保留具体来源卷号用于导航，但作业份数按照片组身份计，不能按保留事件落在哪个副本计数。聚焦来源带确认版本，改判／版本改变后阻断，创建请求含paper_version且服务端精确校验，防止回退另一题。
