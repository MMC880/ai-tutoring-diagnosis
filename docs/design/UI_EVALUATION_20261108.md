# 晋学智辅当前界面测评

2026年11月8日 · 仅评测，未修改应用界面或业务逻辑

后续：用户已授权修复，本轮评测中的四项已完成界面收尾与合成回归，见[修复交付](UI_POLISH_DELIVERY.md)。下文保留修复前的测评与原始截图。

## 结论

当前三入口布局适合给甲方演示，并开始小范围教师试用。下一轮建议集中做首屏重点、登记用语和统计表达的收尾，不再重做整套布局。

产品体验主观评价为 **7／10**：导航、视觉一致性和确认流程已经形成；老师最需要的知识问题和下一步行动仍埋在较长页面中。此评分不是教师实测结果、准确率或商业成熟度评分。

## 本轮实际做了什么

- 对隔离工作区当前应用进行浏览器点击和截图；代码基线`e2899b4`，评测开始时HEAD为文档提交`2338817`。
- 复用专用合成库的只读SQLite备份，另起假AI测试服务。使用3名合成学生、4份作业；没有读取真实资料库。
- 实际查看15张截图，涵盖1366×768、1024×768、390×844三个尺寸；包括首次选人、档案首屏与详情、作业列表、新作业弹窗、核对首屏与底部、班级统计和设置。
- 只浏览和打开／取消弹窗，不提交作业、保存草稿或确认归档。捕获的HTTP请求全部为GET，无外部HTTP请求、模型发送或JavaScript运行异常。
- 检查的15个页面状态没有整页横向溢出；合成库记录摘要和原库文件哈希前后未变。

本轮不是完整功能回归测试，也未测试实际老师独立完成任务、真实识图、长名单、大卷题量、Windows EXE或真实手机设备。窄屏结果来自桌面浏览器尺寸模拟。

## 做得好的地方

1. **主入口容易记。** “学生档案、登记作业、班级学情”各自承担明确日常任务，设置单列；比把辅助工具全部铺在主导航更便于学习。
2. **先选人有帮助。** 左侧姓名和编号同时出现，选中状态明确；首次不自动替老师选人，降低把A的记录看成B的风险。
3. **整体观感统一。** 深青色导航、浅底色、白色内容区和主按钮风格一致，适合作为老师工作台，没有突出的装饰干扰。
4. **待审与确认有区分。** 核对页底部保留保存和确认操作，原题／作答详情可以展开；这些状态和依据不应因简化界面被隐藏。

## 建议优先改的四处

|优先级|实际观察|对老师的影响|建议收尾方式，尚未实施|
|---|---|---|---|
|优先|档案首屏主要展示确认历史计数和四个统计卡；“二次函数顶点式、两份作业反复出现问题”等线索在下方|老师选人后，不能第一眼回答“这个孩子要补哪里”|将需要关注的知识问题、出现过的作业次数、最近复查表现和查看依据入口提到前面；只属标签线索时仍明确待核对|
|优先|1366×768核对首屏叠放导航、页标题、子导航、选卷、学生身份、日期和范围说明；题目区域接近首屏底部，底部还有固定操作条|老师进入核对后要先滚动，才能开始看题|合并重复身份与选卷信息、压缩上下留白，让第一道题在首屏可见；具体疑点和未确认状态继续保持醒目|
|优先|班级页通过“当前整卷”的学生卷子选择器确定批次，显示“2／2”“1／2”“二元有效作答”等表达，页头还出现全库人数|容易混淆统计的是一名学生、一份试卷还是整个班；数字分母含义不直接|显示作业名称及“当前作业批次”，用“已确认2人／已收2人”“可判定2次作答中1次错误”等完整中文；保留未知与缺材料单列，不扩大现有统计范围|
|随后|新作业弹窗要求手填批次代码，说明文字较密；在768高屏幕内出现内部滚动，底部按钮贴近边缘|普通老师需要理解系统编号，填写和提交需要额外寻找|将批次解释成“这次统一作业／考试”；后续讨论复用已有作业或自动编号。当前先减少重复说明、调整按钮位置，不改变归属与确认规则|

## 手机方向的观察

390×844下导航和内容未整页横向溢出，但学生名单、说明和身份信息纵向堆叠，档案首屏几乎看不到具体知识问题；核对页底部固定操作条进一步占用空间。

因此，目前是桌面界面可以在窄屏显示，不能称为家长移动端已经准备好。电脑端先完成试用；将来移动端单独整理信息层级，名单可按需展开，首先呈现已授权的本孩子反馈，不照搬老师管理界面。

## 封装前后的建议顺序

先确认本测评中的三个优先项是否作为收尾范围。若获准，只做现有内容排序、布局压缩与文案澄清，不增加新业务模块。完成针对性页面检查后，再按封装方案处理Windows启动和交付验证。

拖拽上传属于已提出、尚未实施的便利性需求，可另行确认。跨次班级累计分析属于数据关系和统计能力增量，不应当作为换几个UI文字就已完成的功能。

给甲方演示时，建议直接用“某知识点在两份作业中出现问题”的合成案例，展示问题记录、原题依据和后续跟踪位置。不要仅凭三个学生的演示，就宣称已验证大班级效率或教学效果。
