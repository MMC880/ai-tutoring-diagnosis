# v0.20 班级共性知识问题

目标：老师在本批已确认原卷中看到哪些知识点涉及多名学生，逐生追溯后决定集中讲什么。沿用既有本地单用户网页/Python/SQLite；不增数据表、不上传资料、不自动诊断或出题。

方案：在现有按题号统计前增加知识问题区。复用个人档案build_learning_analysis，先逐生按确认版本与原件去重，再按稳定知识条目合并；文字标签按知识名称+题型单独保守归组。同一条目跨资料版本、名称和题型可一起看；同名不同条目、未关联标签不混并。保留原题号统计，不用相同题号替代知识身份。不新增全自动语义映射或班级固定名册。

每组显示涉及待补齐的独立学生人数、去重记录数、错误/部分正确/正确/待核对/缺材料分布、曾用名称与题型。待补齐只包括INCORRECT/PARTIAL；缺页与模糊不当不会，复测不并入原卷。多人线索仅提示可考虑集中核对，同生多错只算一人，不宣称反复薄弱或掌握。未标知识/题型数单列。

证据保留学生本地编号、称呼、原卷/批次/题号/确认事件及版本，可只读回看当次原答/教师记录/原件，也可打开该学生档案。旧确认在有待审修订时仍显示并标记；草稿不进入统计，改判用最新确认。异步返回须核对当前批次、页面代次、显示证据身份与学生归属，切页或开窗后取消迟到操作。

后端在summary添加class_analysis字段，旧字段不变；新增class_analysis.py只读组合已有分析。前端新增class-panel.js，复用既有个人档案与证据接口；班级摘要读取加页面/原卷代次守卫。UI按涉及学生数、待补记录数与稳定ID排序，不给无法核准的应收人数或掌握率。

验证：隔离合成库测去重、身份、人数、批次/学生隔离、改判与未确认版本；浏览器测显示、证据回看/档案跳转、迟到响应和窄屏。完整后台与关键原流程回归后，备份本机，更新0.20只读核验数据未变，源码白名单打包并本地Git提交。真实老师集中讲解是否省时、知识关联与识图质量仍需实测。

实施选择由本轮开发判断作出，依据用户已确认班级共性主线及持续开发授权；未将方案称为老师已验收。
