# v0.4 照片响应接收与题号完整性

2026-11-05。用户再次要求沿照片核心主线连续开发，沿用Python/SQLite/Pillow，不更换服务商或模型、不访问真实学生资料。

## 目标与依据

现有整页合成请求曾读取响应超时；单题合成成功。不能据此判断准确率，也不能猜测旧失败原因。本轮改善接收机制并防止漏题被当作完整转写，不承诺整页可靠性已解决。

流式格式参考[DeepSeek Chat Completions官方文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)：SSE增量、终止标志和用量。用户书生服务文档页本轮无法读取正文，这不证明其指定模型渠道支持相同功能。因此新增图片分段接收选项，默认关闭，配置变化使图片会话验证失效；没有默认切换协议、自动降级重发或自动增加Token上限。

复用检查：读取find-skills并检查skills.sh目录及OCR／handwriting搜索。笔记样式、字体生成候选不解决数学识别；通用OCR说明或模型榜单没有本任务手写数学实测证据，未安装候选。继续复用Pillow与urllib，依据协议做小范围适配，不引入新的云OCR或本地大模型依赖。

## 行为

1. 可选image_stream配置只作用于图片探测／转写，文字仍使用原完整JSON路径。请求预览明确接收方式、学生、本卷版本与目标。流式只接收最终答案content，不保存或展示reasoning_content，不执行工具调用。
2. 完整终止且finish_reason有效才进入既有转写解析。中断、协议错误或总时长检查终止时保留UNKNOWN和已收到的合法usage，不把部分JSON当完整结果，不自动重试。保持单次阻塞45秒空闲超时；流式在每个网络块之间检查120秒总耗时，最后阻塞仍可能延长至约165秒。总响应不超过1MB，单行不超过256KB，最终文字不超过100000字符。
3. 自由区域增加可选“本次应有题号”清单。1～100个不重复非空字符串，每项最多40字；仅本地元数据，不外发清单或身份。单题目标与清单不可同时使用。没有清单时只说明“题数完整性尚未核验”，不声称自动数齐。
4. 返回结果显示应有、识别到、漏识别及清单外题号。少题或读错号保持PARTIAL，识别外题号保留原读号和待核清疑点；老师可以对照原图改号。应用只接受清单内题号；原AI结果、人工改号分别留存。
5. 应有但核对表仍缺的题，在新待审卷中明确保留PENDING及识别缺口。旧原题／作答若已有则保留并注明需再核对；新题留空作答，不用答案补写、不记成不会。原卷未涉及的其他题不变。失败人工兜底遵守相同清单规则。
6. 既有历史保留、重复写入、教师整卷确认与数据本地边界继续有效。恢复前验证清单格式及已保存转写与清单的对应关系；旧无清单备份兼容。

## 边界

本轮只做合成／假服务验收；本机内存Key已在上次升级清空，不从聊天重新装载密钥，不真实发送。模型是否支持本渠道图片分段、整页真实手写质量、少题判断依据及老师省时仍需之后获准实测。
