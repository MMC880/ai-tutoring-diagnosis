# 批次收件工作台设计

依据：用户认可继续开发老师批量作业操作方向，2026-11-07再次要求继续。沿用老师逐生整卷审核、学生本地档案、疑点不能当不会的边界。

目标：让老师从一批已收到的作业中找到待处理学生，看到附件、识读/缺材料状态和重复照片线索，准确进入该学生整卷审核；不用先逐一打开所有学生才知道进度。

方案比较：在班级错题统计内堆加收件信息会混淆未经确认的材料与已确认学情；只加弹窗不方便持续处理。采用独立“批次收件”页面，复用现有逐卷审核、原件和确认流程。此为当前授权方向的最小实现，不新增批量审批或自动外发。

本轮范围：

- 只读API从现有卷面和学生表生成批次清单，无新表、无数据迁移或材料自动归属。
- 显示本批已收卷数、本版已确认数、待审/修订待审、含待核对或缺材料的卷数；这些是不同口径，已确认可仍含缺材料。
- 已收不等于应收。没有班级名单，不能说未出现的学生未交，也不能把现有3名学生冒充10人已收齐。
- 各学生显示编号、称呼、卷名、版本、作业附件数、照片数、参考附件数及疑点题数。附件数量不是页数，不能据此推断整卷完整。
- 同一学生卷内按内容hash提示重复附件；同批不同学生使用相同内容照片时只提示核对归属，不删除、不合并、不增加学生错误记录。参考答案不参与重复作业提示，不用印刷题干相同推断重复。
- 按批次和“全部/待审核/有疑点”筛选；“打开整卷”重新读取最新本机卷面后进入原审核台，回到批次可继续处理。支持直接访问#intake及空库。
- 页面请求有代次保护；切页、切批次或旧行版本变化后，迟到结果不能把老师带回旧学生。保留已有未保存更改拦截。

输入输出不含题干、学生答案、提取正文、附件原图或AI请求内容。计数只读本机已存元数据。姓名仍仅在本地显示。

验证：隔离合成学生与照片；空批次、跨批次/跨学生、同hash不同上传ID、参考附件排除、修订与缺材料、重复读取零写入、HTTP访问边界、迟到请求与窄屏。现有真实卷面本轮不做识别或教师确认。

后续另做：应交名单/缺页页序编辑、多文件批量分配、长期任务调度。先验证这一最小入口，不扩成班级管理系统。
