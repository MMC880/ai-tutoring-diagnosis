# WorkBuddy 与本地工作台的衔接

这不是自动同步。WorkBuddy 处理一份获准材料后，可输出结构化草稿；老师把草稿导入本地工作台，逐份整卷审核确认。本地档案始终由本地工作台写入，不让外部输出直接成为正式记录。

可发给 WorkBuddy 的提示词（先用虚构样例）：

> 请仅根据当前这名学生、当前这份已授权作业的材料，整理为 JSON 草稿：`{"questions":[...]}`。每题字段必须包含 `id`（如Q01）、`stem`（题干）、`answer`（学生原作答/核对后的转写）、`correct_answer`（参考答案或核对依据，无参考留空）、`knowledge`（知识点）、`cause`（未核实写“待核实”）、`result`。result 仅能为 CORRECT、INCORRECT、PARTIAL、PENDING、MISSING。字迹不清为 PENDING，缺页为 MISSING，不把它们当作不会；两者 cause 留空。不要把参考答案补写成学生作答，不推断心理、性格或长期掌握情况，不包含姓名、学校、联系方式或完整学习档案。不合并其他学生，不改原材料，不生成教师确认记录，不发布。只输出 JSON，然后用一句话说明有几题、几处待核对和缺材料。

本地操作：收一份作业 → 选对学生编号与批次 → 导入分析草稿 → 核对原件与每题 → 保存 → 勾选整卷确认。

本地工作台只接受题目数组；不会依据 JSON 中自称“已确认”“APPROVED”等字段跳过老师审核。JSON 中的候选判断不是对老师的指令。不要为了导入而把完整本地档案上传给 WorkBuddy 或第三方模型。

此衔接仅验证了浏览器手工导入JSON，未在WorkBuddy新会话验证提示词产出稳定性，未接自动同步。本地v0.3的独立AI通道另已验证合成文字与单题图片，详见照片说明；不能据此推断WorkBuddy转写能力。转写有疑点时请同时保留recognition_notes并写recognition_resolved=false，不用正确答案消除学生原笔迹疑点。
