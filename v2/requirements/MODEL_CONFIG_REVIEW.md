## 结论

1. 现有真实测试入口的默认地址、模型名与用户指定一致；实际 POST 路径、认证头和无凭据停止行为已离线核对。**真实模型自主工具调用仍未验证**，不能将本轮本地 transport 测试算作真实模型通过。

## 本机配置最小修改建议（未实施）

### 老师会看到的行为

1. 保留现有“AI 服务设置”弹窗，加一个“在这台电脑记住配置”选项。建议首次由老师主动勾选；没有再做一套账号或供应商管理界面。
2. 地址、模型、Key 作为完整配置提交；记住时先用 DPAPI 加密并写入，再主动测试。分开显示“本机已保存”和“文字连接成功/失败”。401 不等于保存失败，存储失败不先外发测试。
3. 同一 Windows 用户重新打开软件，自动恢复绑定配置，输入框仍为空，只显示“已从本机安全存储恢复；本次连接未测试”。不因启动自动发送探针或学生资料。
4. “清除本次密钥”明确改为“清除本机保存的密钥”，同时停用活动配置。删除失败要说清“当前已停用，保存项未删除”，不能假报下次不会恢复。
5. 修改接口地址不能偷偷沿用另一个地址的旧 Key。最小版本保留现有完整三项提交规则，不新增空 Key 自动复用逻辑。模型切换本轮也不另做管理界面。

### 数据与安全边界

- Windows 当前用户 DPAPI 加密完整配置；不使用让所有本机用户共享解密范围的 machine-wide 标志。可用 Python 标准库 `ctypes`，无需安装新密钥库。
- 密文建议位于系统当前用户 LocalAppData 的 `JinxueStudentFirst/provider-config.dpapi`，通常仅几 KB；与 EXE 路径、学生归档目录分开，更新或切学生资料目录不更换 Key。目录依据系统 known folder 解析，不硬编码用户名。
- 不放入 SQLite、MD、项目 `.env`、浏览器存储或学生备份 ZIP。不提供任何返回明文 Key 的接口。
- 保存包含版本/完整绑定/结构和损坏检查；写入临时**密文**后替换，失败保留原有效状态。不能写临时明文，也不能加密失败后退回明文。
- 当前 provider 路由只有 loopback、Host 与 CORS 约束；专有桌面令牌目前只保护备份/恢复路由。不能把这称为所有 provider 操作已经过桌面身份认证。方案沿用当前同用户本地进程信任边界，不新增任意文件解密或 Key 回读能力；DPAPI 也不防同一 Windows 用户下已受控的程序。
- 测试使用独立合成配置；不读取、清除老师的生产保存项。Key 在实际调用时仍需短暂解密到进程内存，这与磁盘不存明文是两件事。
