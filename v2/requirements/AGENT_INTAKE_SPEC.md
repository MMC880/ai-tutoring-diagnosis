# 拖给Agent并归档：本轮实现范围

2026-11-10；依据本轮用户明确给出的9步流程及已确认访谈规则。

一次处理一个学生的一份作业，可含多张图片或PDF。复用现有独立Agent窗口、四科入口、学生索引和原件目录；不改1.0，不重装环境。

老师输入明确归档指令时，本地受控工作流解析班级、学生、学科、日期、批次和明确错题号，真实写档、回读后给回执。此步骤不依赖外部模型或OCR，不把身份和全档案交给模型。新学生询问是否建档；重名提供候选让老师选；无日期先记待补。不能把正文中任意数字当题号，疑似、转述AI或不明确的判断不能写成教师事实。不能可靠理解时请老师补充，不猜测。

原件按内容哈希保留；SQLite记录上传流程、作业、教师错题和AI候选来源；正式记录与对象使用事务提交和写后回读。重复提交同一请求返回原回执；同生同科相同或部分重叠材料提示已有记录，不静默新增。断电时未关联的原件可能保留，不当作归档成功，不自动删。

界面显示文件清单、图片缩略图、PDF页数；图片预览/识别失败仍可保存原件并显示原因。图片/PDF沿用归档单文件15MB、一次12份限制；模型分析仍沿用既有最多3图、每张2MB边界。本地归档和外发分析明确区分。保留原件不等于识别通过。

后续查询在本地按学生、学科、作业实际日期取历史；日期待补单列。题号相同但不同作业是不同记录。知识点次数仅依据已有明确关联，没有关联时说明无法据此统计，不能编造次数。AI候选不计为教师确认错误；一次错误不称长期薄弱。

本轮不做自动批改、三级训练、班级分析、全知识点自动归类、新EXE或真实材料外发。已有AI待确认笔记工具保留。收到原件不自动运行识别；老师可另发分析指令。
