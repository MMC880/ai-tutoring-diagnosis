## 已确认的产品目标，不重复访谈

晋学智辅是供教培老师使用的本地教学 Agent 软件。软件管理学生、四科资料、原件、学习记录、MD、Skills 和任务状态；Agent 通过受控工具读取材料、分析与归纳，后续生成针对性训练。它的长期目标是：

作业 → 错题记录 → 错误类型与知识点归纳 → 针对性训练 → 复测反馈 → 更新学生档案。

- 数学、英语、物理、化学分别管理；先用数学验证教学流程，不把四个入口当成四科能力验收完成。
- 老师明确的结果、AI 候选、错因推测和独立复测分别记录；不把单次对错认定为长期薄弱或已经掌握。
- 无心理档案、人格标签或心理推断。
- 老师自然语言交代任务，不应为已有信息重复填表。明确要求保存的原件与教师事实可以直接保存并返回回执；AI 推断不能自动成为正式教师事实。
- 原件和历史保留；学生身份及完整档案留本地，外发限当前授权的学生、学科和必要材料。
- 优先结构化摘要和历史记录；原图按需读取，不默认发送全库照片。
- SQLite 管理索引、有效事实、修订和状态；MD 保存可读记录与待确认分析；Agent 调用工具，不能凭一句“已保存”代替实际写入。
- 三级训练是整体方向，最新明确的当前阶段仍先验证历史读取与分析，不擅自提前扩展。

建议用“一名学生、同一学科的两次作业”检验真正的教师任务：老师选择学生并交代本次任务后，Agent 自己按权限查历史、按需看图、引用具体作业/题号，区分同知识点与同错因，保存可修改的待确认 MD；重开软件后仍可找到本次结果和对应依据。读取失败、推断不确定或没有真实工具执行时明确展示，不要求老师另到多张表单重录。

这条目标不代表已经通过该验收，也不把后续正式入档、三级训练或复测自动纳入当前批次。

## 第一轮已确认：以对话纠正为主要修改方式

此前已确定 MD 要可读、可修改、可长期保存，但尚未明确外部手改 MD 与老师确认记录的关系。现有代码中的初始归档 MD 是历史快照，后续有效修订保存在结构化记录；不能悄悄将任一旧文件当成最新事实。

具体场景：老师发现 AI 分析的其实是第 6 题，在保存的 MD 中把“第 5 题”改为“第 6 题”。下一次 Agent 读取时，这份修改应怎样生效？

- **用户选择 A**：老师平时直接在 Agent 对话中纠正，系统保存有版本的新笔记与回执，保留旧稿。直接修改的 MD 也可以交回 Agent，但先识别为修改候选、核对来源后再采用；不会静默改写老师已确认事实。老师不需要再填表或编辑 JSON。
- **未选择的备选 B**：MD 直接作为当前学习档案，文件保存后 Agent 即按修改内容继续，软件索引随之更新。本阶段不安排外部文件变动自动同步。

确认依据：本轮用户回复“A”。这是需求决策，尚未实现对话纠正和版本回执；不把这次文档更新称为软件功能已完成。纠正针对明确内容生效，不把老师更改题号扩展为认同 AI 的其他分析或错因。

## 第二轮已确认：Agent 根据老师指令选择教学流程

已确定软件封装教学 Skills 与流程，老师以对话交代任务；尚未明确日常任务是否要求老师手动选择 Skill。

具体场景：老师上传某个学生的数学作业，说“整理这次的问题，看看和以前有没有关系”。

- **用户选择 A**：Agent 根据指令和当前学生、学科、材料自动选择适用的教学 Skill/流程，说明本次准备做什么并在已有授权内执行。老师不必理解或选择 Skill 名称；目标含糊、缺少适用流程或权限不足时说明情况并询问，不猜测扩权。Skills 的可查看与具体管理方式留待后续，不在本轮新增管理界面。
- **未选择的备选 B**：老师每次先选“作业整理”“历史问题分析”等流程，再交代任务；本阶段不将手动选流程作为日常前置操作。

确认依据：本轮用户回复“A”。自动选择教学流程不等于自动批准正式入档、发布练习或全部历史外发。这是需求决策，尚未实现教学 Skill 自动选择机制。

## 第三轮已确认：以一次教学任务统一确认范围

现有界面将读取历史、读取原图和保存笔记分成多个开关。用户已经要求当前学生/学科范围、摘要优先、原图按需及待确认笔记；本轮不重复决定这些边界，只讨论老师是否需要逐项操作开关。

具体场景：老师已选学生 A、数学及本次作业，交代“分析第 5 题，看看和以前的问题有没有关系”。

- **用户选择 A**：软件用一份简短任务说明汇总本轮允许的材料和动作，老师一次确认后，Agent 自行按需查询该生数学历史摘要、读取本次所选材料、保存待确认分析与 MD，并展示实际引用来源。历史原图没有被默认加入；需要额外历史原图时明确请求，其他学生/学科和正式教师记录不在本轮权限内。已有有效的同范围授权可以复用，不为每个工具重复询问；重启不自动恢复外发授权。
- **未选择的备选 B**：保留逐项开关，老师分别批准读历史、看本次图片和保存待确认笔记；本阶段不将逐个工具确认作为日常操作方式。

确认依据：本轮用户回复“A”。此处确认的是任务层操作方式；具体界面样式、运行时组件、授权有效期细节仍不是已确认实现。不在访谈阶段修改现有权限逻辑。

## 第四轮已确认：按教学任务保存对话，重开后继续

已有目标要求原件、分析 MD 和学生历史长期保存，用户也强调软件管理任务流程。完整对话是否应随任务恢复，尚未在本次需求中直接确认；现有代码未保存完整聊天消息。

具体场景：老师今天分析学生 A 的数学作业，明天重新打开，想补充“刚才第 5 题的分析再改一下”。

- **用户选择 A**：按学生、学科和作业任务保留本次对话、实际工具回执及分析笔记；明天打开该任务，可以看到之前讨论并继续。新作业可以另起任务，历史资料仍可按需查询。本地显示旧对话不等于将全部旧对话/原图再次外发，也不自动恢复上次的外发权限；恢复记录不承诺自动续跑中断的模型任务。
- **未选择的备选 B**：只长期保存作业原件、结构化结果和 MD，每次聊天重新开始；Agent 按需读档案继续分析，旧聊天不保留。本阶段将完整任务对话的本地保存列入需求。

确认依据：本轮用户回复“A”。这是需求确认，尚未实现完整会话保存；不引入全新的聊天平台、多 Agent 系统或界面改版。

## 实现路线比较（待用户选择）

前四轮已经明确主要交互：对话纠正、自动选择教学流程、按任务统一确认范围、重开同任务继续讨论。已有的两次作业、真实工具调用、证据引用和待确认 MD 验收目标继续沿用。接下来比较实现路线，不重新询问已经确定的业务方向。

两条路线均保留现有 Electron、React、FastAPI、SQLite、学生资料、业务工具和 MD，不迁移旧项目，不引入整套外部 Agent 平台。依据本轮官方上游研究，方案仅是候选，尚未安装或验证。

| 路线 | 做法 | 收益与代价 |
| --- | --- | --- |
| A（建议，待确认）：现有产品接成熟 Agent 组件 | 沿用已安装 assistant-ui 的工具展示和历史适配接口；对成熟 Python Agent 运行组件先做隔离兼容验证，通过后仅替换模型/工具运行循环，继续调用现有受限业务工具。当前优先候选为官方研究中已核对的 Python Agents SDK；固定发行版、依赖和接口仍需实施前核验 | 减少自行维护通用 Agent 基础机制，符合用户优先复用的方向；增加一项受控的依赖和兼容验收。SDK 不能自动提供本项目的权限、MD 一致性或教学正确性 |
| B（备选，待确认）：先补现有受限运行循环 | 同样复用 assistant-ui 的工具展示和历史接口，暂时保留自写的四轮工具循环，补必要的持久回执与会话连接 | 新依赖少、局部变更较小；运行状态、取消、异常和重复执行等通用机制继续由项目维护，后续可能再次调整 |

A 的隔离验证必须覆盖指定服务协议、现有权限、工具顺序与预算、关闭外部追踪、显式禁用自动重试，以及失败后回执与已保存结果。验证不通过时保留既有实现并报告，不擅自扩大替换范围。上次真实模型认证返回 401，是独立阻塞；两条路线都不能以本地模拟或换组件代替真实认证及教学任务验收。本轮不重试已保存凭据。

用户选定路线后再形成需求与设计审阅稿。用户批准设计后，才调用 writing-plans 形成可执行计划；当前仍无业务实现授权。
